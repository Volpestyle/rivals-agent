## Delivered behavior

Preparation is the default: exact hashed CM3 or eligible legacy checkpoint loading
through `agent.live_range_bc.load_checkpoint`, train support/live mask, fixed
threshold identity, normal-cooldown distribution and settings contract validation.
It prepares compact-bgr preprocessing and loads on CPU, without a forward pass,
desktop capture or CUDA access, even when the target device is explicitly CUDA.
There is no exploratory H1 adapter or automatic checkpoint fallback.

The settings check uses `harness.calibration(settings, camera_disabled=True)`:
binding profile, swing, cooldowns and patch only. The manifest explicitly says
`no_actuator: true` and `calibration_status: execution_maps_not_validated_or_consumed`.
No maps are inferred, required or consumed by the predictor. This is not an
execution-map or policy deployment approval. The integration owner made this
choice to avoid requiring maps before the sitting that measures them.

Only `--desktop-capture`, a positive foreground game PID, sitting identifier and
native OBS reference can open capture. CPU is the default; CUDA must be named.
The runner never focuses or navigates a window. It contains no import or
construction of `Live`, `Pad`, `pad` or `vgamepad`. It imports existing pure
harness contracts (which transitively load controller constants/class definitions)
and only the `in_range` / `idle_warning` readers from `record`, not its input class.
It does not import `agent.loop` or `scripts/run_range_bc_live`.

The explicit capture path holds the same predictor/model resident for A1/B/A2.
Each phase is exactly 10 seconds warmup followed by 30 seconds measured, total
120 seconds. A1/A2 run capture, proof and evidence; B adds one inference at a
time on a newly captured, copied frame. Outputs are discarded without decoding.
Prior input is unknown (`None`) for every prediction; B retains recurrent state.
This measures active inference cost, not a game-only baseline or policy quality.

Capture defaults to 30 Hz (15..60 allowed), proof checks every captured frame,
and native lossless overlay PNG retention is scheduled at 1 Hz in every interval.
The last 100 ms of every interval admits no new capture, and B admits no new
inference during its last 250 ms. These equal capture exclusions avoid crossing
phase boundaries; report denominators remain the full measured 30 seconds.
The two-queue-slot native writer is shared with the existing harness. Missed
capture slots, missing frames, inference busy slots and dropped/unwritten evidence
are reported, not disguised as matched achieved rates.

Read-only keyboard/focus checks run at most every 5 ms between native calls and
again after capture/proof. Capture-start timestamps include acquisition and proof
cost; fresh range/idle proof must be <=100 ms old. Missing capture, geometry
changes, HUD loss, idle warning, focus loss, keypress, inference errors and a
250 ms prediction-age/timeout refusal end the run without retry. No output can
reach an actuator. A blocked native capture/driver cannot be forcibly canceled
by Python; overruns are detected on return. A hung daemon inference worker is
reported as not stopped, and no further phase is started. Thus the 120-second
schedule bounds admitted work, not an uninterruptible external driver call.

## Evidence and limits

`manifest.json` pins checkpoint/settings/support/decoder identities, runtime
source hashes, device, dependencies, graph, capture cadence and OBS reference.
`events.jsonl` records phase/interval boundaries, monotonic-to-UTC alignment,
capture/proof and prediction completion times. `result.json` reports actual rates,
capture duration, proof and full preprocessing/encoder/head prediction-age
p50/p95/p99, process working set and CUDA allocated/reserved/peak memory at
interval boundaries. CUDA memory describes this process, not the game's memory.
Python allocator memory is reported separately from native working set.

`frames.jsonl` pins successfully written native PNGs. `fps-annotations.csv` is a
blank template with phase, warmup/measured interval, capture timestamps and native
frame paths. Missing evidence has an empty path. Copy this CSV before annotating;
unreadable overlay samples stay blank. Offline `annotate` validates row identity
and retained evidence, excludes warmup, and produces `annotated-fps.json` with
sample count/rate, median/p10, paired loss, A1/A2 drift and cap saturation.
Paired loss is `100 * (mean(A1 median,A2 median) - B median) / mean(A1 median,A2 median)`.
These are visible counter samples, not frame times or 1% lows. A saturated cap
does not establish unused rendering headroom. Incomplete runs cannot produce a
paired summary. Manual annotation itself remains the operator's responsibility.

The operator must keep pose, resolution, graphics, FPS cap, OBS settings and
other workloads unchanged, keep the native FPS overlay visible, and abandon a
comparison if a workload changes. The tool cannot prove those conditions.
Game FPS cost remains **unmeasured**: this worker did not use the game, desktop
capture or GPU and did not run a policy forward pass.
