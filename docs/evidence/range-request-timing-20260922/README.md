The six-label human checkpoint remains a numerical **visual-onset forecast**.
Both positive anchors occur after recorded right-mouse receipt, so reproducing
those labels does not establish when to initiate firing. The next experiment
will inspect observations before the actual requests. Existing labels, model
weights, threshold, horizon and historical results remain unchanged.

arithmetic. Lead accepts that [bounded interpretation](independent-review.md).

actually exploited an input-response cue. No new corpus row or live binding is

## Runtime comparison

[Calibration D](../range-cast-calibration-d-20260922/README.md) established two
scripted pulse-to-cast correspondences. Reusing its empirical video-clock
envelope gives first-LT-attempt-to-emission intervals of approximately 87–158 ms
and 83–154 ms. They include values below 100 ms. This is not a proven physical
latency or a guarantee that input authorized for 100 ms yields a visible cast
inside the same interval.

[Semantic comparison](semantic-comparison.md), [arithmetic](calculation.py) and
[results](results.json) distinguish acquisition, request authorization, API calls
and visual emission. [Saved settings](current-saved-settings.json) were inspected
after D; they are not backdated runtime observations or a deployment receipt.
Source and runtime observation identities remain separate.

## Lead decision and next experiment

Retain the accepted fit and shadow as observational forecasting evidence. Do
not present them as learned pre-request execution. Inspect candidate request
bins n141 and n198 on the existing 100 ms grid, plus previously inspected moving
non-start controls. A positive needs actual received initiation linked to the
observed web cast and the causal anchor's selected target. Earlier or future
targets cannot be substituted. Unknown binding, overlapping controls or target
correspondence must remain explicit; a new request head cannot reuse the old
semantic revision. No new labels are admitted by this decision.

This bounded inspection uses the already-authorized source. It does not request
stationary Idle examples, DPI calibration or another recording to fix software.
Independent-session validation and genuine runtime review retain their existing
roles. Neither the old checkpoint nor a new one has controlled game input.
