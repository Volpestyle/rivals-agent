1. **Required — make paired initialization part of the core contract, not only the reader contract.** Preregistration section 4 (lines 82-88) isolates W's dropout RNG and preserves initialization *methods*, but does not require equal initial shared tensors across H/W/N. Section 8 explicitly provides an independent initialization stream for R; that protection is missing for the core contrast. Today `train.fit` seeds once and constructs `Policy`, whose history module is constructed before the LSTM and heads (`model.py:85-88`). Simply removing that module for H/N and constructing it for W consumes different RNG draws and changes the common LSTM/head initialization. Different feature constructors can do the same to I. This is avoidable variation in the advertised per-seed contrasts, especially with only three seeds; it is not evidence of a history effect.

   **Fix:** specify stable initialization streams for the common recurrent core/heads, shared frozen-feature projectors, and each arm-specific encoder/history branch. Require same-seed H/W/N projectors/core/heads to start byte-identical, and I's same-shaped common core/heads to match. Specify the seed derivation in the launch contract. Test shared initial-tensor hashes and window order, not merely repeatability within each arm. Keep historical A's construction untouched. For R, explicitly define how the existing LSTM input columns are preserved when its extra 64 reader inputs enlarge the matrix; do not rely on the phrase “same seed” to provide that guarantee.

2. **Required — decide the zero-treatment case before buying the null comparison.** Section 6 correctly admits that there may be no eligible physically idle run, but only says to report an inactive intervention. Section 9 still selects normally and section 12 still pays for all twelve fits. If the sidecar assigns weight 1 to every scored element, H and N are the same experiment once initialization/order are matched; three additional N fits cannot answer target imbalance. N's tie priority can then produce “No-filter control wins” without any actual filtering contrast.

   **Fix:** move the already-required per-head effective-weight audit to the pre-fit gate and register an explicit zero-effect disposition. Either reuse the identical H fits for an explicitly inactive N condition (judge records “target-imbalance contrast untested”), or stop for a design/budget decision before any core result. Preserve the original k=30 and weight=0.1; do not search for a threshold that produces a desired idle rate. This also covers runs that exist in the sidecar but contribute only masked/burn-in rows: inspect effective scored loss mass, not just raw run counts. A nonzero but small treatment remains descriptive, with no invented post-hoc minimum-effect threshold.

Exercise I's normalized trainable encoder and W's history/dropout path as well as H; only H needs the registered full-seed repeat. Count extraction, hashing, CPU proofs, all per-epoch dev evaluations, A reread and that repeat inside the 16-hour total.
