## (3) MPS-only memory disposition: correct

`check_memory` behaves as follows:
- A null `peak_memory_bytes` is accepted only on MPS, with **all** of the following:
  - `peak_memory_status == 'unmeasurable_mps'`;
  - finite nonnegative `sampled_driver_high_water_bytes`;
  - `memory_sample_source == 'torch.mps.driver_allocated_memory'`;
  - `memory_sample_interval_ms == 10` (int);
  - integer `memory_sample_count >= 1`.
- A numeric peak must be finite and nonnegative, and cannot claim `unmeasurable_mps`.
- CUDA always requires `peak_memory_source == 'torch.cuda.max_memory_allocated'` and `peak_memory_reset is True`.
- It applies to A and, through the proxy report, to R.

My probes:
- **Accepted:** a valid MPS null disposition; a numeric MPS peak with no status.
- **Rejected:**
  - interval 10.0 (float) or 20;
  - sample count 0, `True` or 4000.0;
  - a sampled value that is negative, a string or a bool;
  - a status typo;
  - a wrong sample source;
  - a numeric peak together with `unmeasurable_mps`;
  - a negative peak;
  - a null peak with the status alone (KeyError, which becomes INVALID).
- **CUDA rejects:** the full MPS null disposition, a numeric peak labelled `unmeasurable_mps`, and `peak_memory_reset=false`.
- No memory value reaches S, K, eligibility or selection.

## Notes (not blocking)

1. **Per-fit predecessors are implied, not checked.** Phase-2 execution records carry no per-fit predecessor identifiers. The Amendment's "every fit carries the same `A_control_gate` and `H0_repeat`" is enforced only through the single pinned gate and timestamps. That is sufficient with one gate per packet, but a runner-side predecessor field would make it checkable.
2. **Failed attempts are trusted, not verified.** The amendment says the aggregate budget includes failed attempts and retries. The judge can only lower-bound `elapsed_compute_seconds` by the 13 accepted intervals, so honest accounting of failed containers remains the runner's attestation.
3. **The gate file is required even when not used.** The CLI requires `--phase1-gate` and its pin for INCOMPLETE packets too, though it compares them only for COMPLETE packets. This is harmless.
4. **The runner has not adopted this yet.** The amendment itself notes that the runner/Modal orchestration and `FIT-RECEIPT.md` dependencies must adopt the Amendment-3 phase delta before launch.
