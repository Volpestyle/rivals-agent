## Findings addressed

- **F1:** the four shared doubles now use `RawValue`; cancellation is a raw byte flag. The safety callback, supervisor and cancellation path acquire no shared semaphore/Condition lock. Each field has one writer on the current Windows x64 target. This relies on that target's aligned scalar loads/stores, not a portable guarantee of a coherent multi-field snapshot. Timestamps are sampled before the local clock check so a concurrent fresh publication cannot appear to come from the future relative to an earlier local sample. Existing age, lease, deadline and takeover bounds are unchanged.
- **F4:** after its second clock sample, `execute` breaks when the schedule has ended, instead of calling `min()` on an empty set of future segments. Cleanup still runs through `finally`; no late input or extension is introduced.
- **F5:** adopted the reviewer's three full-supervisor tests for a blackout over one second, range loss, and takeover during yaw. The new parent-death regression uses **real spawned processes and hard termination**, the production shared-state allocator, the real `CameraPad`, and a fake device. It arms opener/yaw, kills a supervisor while a legacy semaphore is deliberately held, verifies that the old lock remains abandoned, and requires neutral plus one detach despite it. The heartbeat assertion permits 150 ms of test scheduling slack above the 250 ms threshold; this is not a change to the live threshold or a hardware timing guarantee. A deterministic clock-crossing regression covers F4. Exact commands and exit codes are now included in the owner logs.
- **F3:** cheaply removed the transitive gameplay import. The driver contains the existing small read-only foreground-PID check directly, with the same Win32 signatures and positive-DWORD validation. A fake Win32 test covers matching/mismatched PID, missing window and takeover, and refuses an `agent.loop` import. `agent/loop.py` is therefore removed from the runtime pin set. No gameplay module was edited.
- **F2:** no wider input authority is inferred from CLI options. Per the lead, the live grant will pin `--deflections 0.45 --seconds 20` and its outer scope. The schedule and one bounded walk/RT opener are unchanged.
